# 资源审计 v02 · 作品切换后的 GPU 占用

2026-10-25，v09 收口后复测。工具：`node scripts/memory-audit.mjs --rounds=2`（需先 `pnpm dev`），原始数据见同目录 `memory-audit.json`。

测量方式：DEV 下从 `window.__harborDebug.gl` 取一次 `WebGLRenderer` 引用，每次切换后等待 2.5 s 读取 `renderer.info.memory`。环境为 Chrome / SwiftShader，读数与真机不一定相同，但同一环境内的**增量**可信。

## 读数

| 采样点 | textures | geometries |
| --- | --- | --- |
| 基线（渔港） | 42 | 83 |
| 第 1 轮 渔港 | 42 | 83 |
| 第 1 轮 月湾 | 42 | 80 |
| 第 1 轮 云门 | 32 | 31 |
| 第 1 轮 蓝洞 | 10 | 387 |
| 第 2 轮 渔港 | 47 | 84 |
| 第 2 轮 月湾 | 47 | 80 |
| 第 2 轮 云门 | 37 | 31 |
| 第 2 轮 蓝洞 | 15 | 387 |

第 2 轮各作品相对第 1 轮只多一次性的 +5 纹理，第 2 轮内部不再增长。

## 结论

1. **不是每次切换泄漏。** 之前记的「+2 纹理/次切换」已不再复现。整轮来回后增量停在 +5，第二轮内所有作品读数持平。
2. **+5 纹理是一次性分配**：首次进入蓝洞（`meshPhysicalMaterial` 开启 `transmission`）时 three.js 建立透射渲染目标，之后常驻。属于引擎级缓存，不是本项目泄漏。若在意首次进蓝洞的内存峰值，可把蓝洞的 `transmission` 降为 0 或改用屏幕空间近似。
3. **+1 几何体一次性分配**：首次离开渔港后固定多 1 个几何体（83 → 84），之后不再增长；疑为引擎内部全屏绘制用几何体。量级可忽略。
4. **已修复：云门每次访问泄漏 1 个几何体。** `createCloudGate` 的雾墙平面直接 `new THREE.PlaneGeometry` 而没登记到 `geometries` 集合，卸载时不会被释放。改为登记后，连续两次进入云门，几何体稳定在 30/31，往返渔港不再累加（见下方复测）。

修复前后对比（同一路径 渔港 → 云门 → 渔港 → 蓝洞 → 渔港 → 云门 → 渔港）：

```text
修复前: 83 → 30 → 84 → 387 → 84 → 31 → 85     （每次进云门 +1，永久累积）
修复后: 83 → 30 → 83 → 386 → 83 → 30 → 83     （持平）
```

## 仍未覆盖
