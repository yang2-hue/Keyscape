# 第一颗成品：资产制作与接入

先完成一颗灯塔渔港，达到美术与交互验收后，再制作其他题材。原型中的程序化建筑只用于验证比例和操作，最终可以整颗替换，也可逐个替换。

## 制作顺序

1. 以 `public/references/harbor.png` 为美术参考，确认一个主视角和键帽轮廓。侧面与背面必须在同一空间里自洽；不用独立生图拼凑互相矛盾的结构。
2. 可用图生 3D 获取地形／建筑粗模。透明水体不要烘焙进粗模；底座、海床、岩石、建筑与船分别保留。
3. 在建模软件清理穿插、背面、法线及多余碎片，检查灯塔、房屋、码头的比例。保留可编辑源文件。
4. 导出自包含 GLB，通过页面“导入作品”先检查轮廓、旋转与近景。只交一颗试验资产，不先批量生产。
5. 根据实际模型重做水体、反射、阴影与相机。美术通过之后，再压缩纹理、合并静态件与测试手机性能。

## 建议交付

- `harbor-v01.glb`：glTF 2.0，贴图内嵌；当前入口上限 50 MB。首颗目标尽量低于 15 MB，属待实测的预算。
- 可编辑源文件（如 `.blend`）、正面／背面截图、概念图。源文件不需要在网页里运行。
- Y 轴向上，场景单位米；键帽沿 X/Z，底面位于 Y=0，正面朝 +Z。导入器会适配尺寸，但不会纠正资产朝向。
- 建议命名：`KeyBase`、`Terrain`、`Rocks`、`Buildings`、`Boat`、`WaterSurface`、`WaterVolume`。独立对象便于网页接管材质和动态；当前通用预览不会自动识别并替换水体。
- 先使用标准 PBR 材质：BaseColor、Normal、Roughness／Metalness。不要把高光、强光影、透明水体烘焙成不透明贴图。透明效果需在实际浏览器中复核。
- 第一轮用未压缩网格和 PNG/JPEG 贴图；当前未配置 Draco、Meshopt 或 KTX2 解码器。

## 首颗验收

- 远看能辨认键帽轮廓，主体比例和色彩有主次；不会因堆细节失去视觉焦点。
- 近看海床、岸线、建筑有真实体积，背面不是空洞或重复贴图。
- 旋转 360° 没有穿帮；恢复视角与近景都不裁切主体。
- 水能看到有纵深的海床，透明排序与反射没有明显破面。
- 页面在普通笔记本与一台真实手机上能稳定交互；帧率和资源预算测量后记录，不凭开发机推断。

## 接入方式

现在可直接在本地导入 GLB 检查。正式作品确认后，将文件放入 `public/models/`，再把作品信息提取成独立清单，并为该资产编写水体与动画适配。不要把用户机器上的绝对文件路径写进网页代码。
