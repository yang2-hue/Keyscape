# 推进顺序与验收

## 01 · 交互原型（已实现，非最终美术）

单键展厅、两件原创程序化习作、拖动／触摸旋转、近景／重置、光照、暂停、美术参考与本地 GLB 导入。构建和浏览器验证记录在 `outputs/`。

## 02 · 程序化微缩基线（已实现，美术待验收）

art-v05 起默认入口改为分离构建的程序化场景：分离地形、礁石、石屋、弧形陶瓦、百叶窗、灯塔、码头、植物、船和鱼；统一材质与凹凸纹理，使用正交相机、软阴影和 SSAO 等后期。此后 v06–v08 补齐月湾动线（岸阶／主路／支路／塔门）与夜间扫光。旧 GLB 组装版本（`Harbor.tsx` 及其 `harbor-art`／`harbor-surface`／`mesh-repair`／`HarborArchitecture`）于 v09 删除，二进制归档到 `work/archive/public-models/`，`public/models/*/source.json` 保留来源与校验记录。当前代码场景尚未导出为 GLB，也未通过用户美术验收。

验收：主视角成立，旋转无明显结构穿帮，近景能读出独立细节；主体几何和材质可控，代码或模型路线均以实际画面验收。

## 02.5 · 工程收口（v09）

修掉三类会反复咬人的问题：暂停／减少动态时空转渲染（改为 `frameloop` 按需）、错误边界崩一次不可恢复、深链只认一件作品。参考图由 4×2.5 MB PNG 转为 webp 两档（首屏缩略图 22–40 kB），构建产物 57 MB → 2.3 MB。检查脚本从被忽略的 `work/` 收敛为受版本控制的 `scripts/verify.mjs`，13 项断言覆盖深链、注波、渲停、移动端点击区。

验收：`tsc`／25 项单测／构建／`pnpm verify` 全绿；暂停后 2.5 s 内渲染 0 帧；移动端可点区 ≥44 px。

## 02.6 · 月湾产品验收（v09）

按 `docs/crescent-product-acceptance.md` 的 5 项要求出了逐项对照，材料在 `outputs/crescent-acceptance-v09/`：6 张取景截图（主视角／俯视／码头／小屋／灯塔／夜景）、12 秒扫光录屏、`check.json` 里 11 项断言。

结论：码头过渡（23 级、落差 0.30、最大级高 0.0167）、灯塔入口（门紧贴主路、朝岛内、塔院半径 0.17）、夜间扫光（26 秒一圈，暂停与减少动态均冻结）通过；**台地与入户通路的铺装辨识度、夜景光束强度**偏弱，等用户判定是否调整。真机性能仍未测。

工具：`pnpm accept:crescent`。取景走 DEV 专用 `window.__galleryCamera`，构图可复现；录屏用 CDP 抓帧 + ffmpeg `image2pipe` 合成（Playwright 自带 `recordVideo` 在本机因 ffmpeg 缺 vp8 编码器静默失败）。

## 03 · 材质与叙事

已接入水面、透明侧壁、岸边浅色波纹、船体浮动、四条鱼的路径游动，以及晴天／小雨联动。小雨包含局部雨丝、落水涟漪、光照渐变与增强的船体摇晃。先打磨这些现有效果，不同时扩展音频、复杂风场和新天气。灯塔光束、鱼摆尾与精细折射仍待制作。

验收：日／暮两种光照下主体清晰、透明体排序正确、暂停完整、静态模式舒适。

## 04 · 性能与小型展集

真实设备测量后引入像素比上限、阴影／折射分级和纹理压缩。首颗通过后，再做蓝洞与一颗不同题材的作品。完善异步加载、缓存、失败重试与正式作品清单。

验收：以选定手机和笔记本的测量结果为依据设预算；3 件正式作品共享交互语言，各自构图成立。
