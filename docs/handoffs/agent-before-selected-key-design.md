V3 灯塔渔港与蓝洞单键图是已认可的美术参考。整体键盘、超现实等后续探索大多未获认可，不能默认沿用。程序化原型用于验证交互，不能宣称已达到参考图的细节与材质质量。

当前主入口 art-v05 是分离构建的程序化海岸基线：地形、礁石、三栋石屋、弧形陶瓦、窗框、灯塔、码头、植被、船和鱼均由本地代码构建。使用正交相机、共享材质与凹凸纹理、软阴影、环境遮蔽及克制后期。入口 src/CoastalStudy.tsx；几何在 src/coastal-study.ts，材质在 src/coastal-materials.ts。此阶段参考原仓库实际微缩作品，不宣称达到写实概念图或用户美术验收。蓝洞仍是早期习作。

此前 Aholo GLB 与离线交付完整保留，当前主视图不加载它们。src/Harbor.tsx 保留历史生成模型组装和复用的天气组件；不得再把旧 GLB 集成状态写成当前默认展示。程序化场景尚未导出为独立 GLB。

用户拒绝首轮粗模及随后拼装建筑、围合水坑的修正版本。当前优先美术质量，停止功能扩展。art-v03 修正图生输入中的干盆地，已通过国内站标准版重建开放海岸主体（4336818，目标 30 万面、实际 285915 三角形）。当前使用 public/models/harbor-v02/terrain.glb，船和鱼沿用 v01。移除了旧的程序化建筑叠加；显示副本调整海床、替换干模型切面和底座，水体使用物理透射与折射、岸边浪线和水下光纹。原件不改写；显示修改未导出为组合 GLB。建筑、植被和背面仍有明显简化，不能宣称已达到参考图。

art-v04 沿用同一主体，无新增生成。水面和切面改为共享一次离屏颜色／深度捕获，捕获时隐藏整个水体，防止自折射与重复海床；按深度近似颜色吸收，补齐沙底、保留朝上的边缘海床，泡沫限于岸线。主视角略拉近。该水体是自编实时近似，不能继续称为 Three.js 物理透射材质或完整物理模拟。当前证据目录 outputs/art-v04；建筑与植被资产仍未达到参考图精度。

用户再次强调参考 resin-diorama-collection，并拒绝当前观感。已重新通过 GitHub 集成核对源码，并在同机浏览器对照原版 resin-bay 与当前版本，证据见 outputs/reference-audit-v01。不能混淆原仓库的实际程序化作品与后来生成的写实概念图。

art-v05 已重建原作同类的分离几何与统一材质基线。正交近景、复位、背面、动态与手机检查记录在 outputs/art-v05。高度场已支持实例变换，装饰实例可跳过遮挡采样。现有融合 GLB 保留原件，不再通过反复切裁与调水色承担主视觉。Aholo 可用于经检查的独立配件，不能以整块生成模型代替整个场景的可控构建。暂停为同一问题追加自动生成。用户没有验收新基线前，不扩展题材、天气或功能。GPU 高度场水波、局部船体水面采样、真实环境图反射与更精细植物仍未对齐原作，不能宣称整个参考实现已完成。详见 docs/reference-implementation-audit.md。

## 交付顺序

先完成一颗可运行的作品，再打磨正式资产，然后扩展到三件。概念图 → 一颗粗模 GLB → 浏览器验证轮廓与旋转 → 资产清理 → 材质与轻动态 → 性能检查。不要等待所有资产完成才写展示页，也不要先批量生成大量模型。具体制作约定见 docs/asset-pipeline.md，阶段验收见 docs/roadmap.md。

## 技术与分层

- React、TypeScript、Vite、Three.js、React Three Fiber、Drei；当前本地运行，无后端。
- 页面状态与场景、模型加载、材质／动态分开。单件原型允许小规模共置，出现复用与复杂度后再拆分，不先建大型框架。
- 正式资产用自包含 GLB，地形、建筑、船、水面和水体尽量分离。源文件可选交付。透明水体优先在网页根据资产配置，不能依赖图生模型直接还原。
- 尽量使用本地环境与字体，外部资源必须有明确加载与失败处理。
- 导入资源需校验、居中、控制尺寸并释放显存；异步旧请求不能覆盖新作品。用户文件默认只在本机处理。

## 可借鉴经验与限制

参考仓库：https://github.com/luoban25/resin-diorama-collection ，已检查版本 ce7a3e4d713411be8d3743ee1487d27f2fb84fb8。

- 借鉴“页面／场景编排／效果逻辑／模型材质”的分层思路。
- 对参考作品这种清晰的微缩风格，程序化建模可承担主体和重复细节；是否需要专门资产取决于目标风格，不能把整块图生 3D 当作必经路线。使用固定随机种子，保证场景可复现。
- 水面与透明侧壁分别考虑；折射捕获应排除水体自身，避免递归。先做简单可控的视觉，再按资产需求加入折射和焦散，勿直接复制整套重效果。
- 若采用 GPU 水波模拟，使用固定步长、限制补帧次数；不要每帧通过 React 状态驱动连续动画。
- 重复物体优先评估实例化；正式版按真实设备帧率、像素比、阴影与折射成本分级。软件渲染截图不能证明手机性能。
- 原仓库未确认 LICENSE，复用实现思路，不能直接复制源码或资产作为可发布内容。

## 体验与验收

- 艺术内容优先，界面少而明确；不添加调试参数面板、无关功能或大量说明抢占作品。
- 提供旋转、近景、恢复视角、轻动态暂停；尊重系统减少动态设置，支持触摸和键盘操作。不要让天气与粒子遮挡作品。
- 交付前运行构建、相关真实文件测试和桌面／手机布局检查；检查实际 WebGL 场景和交互，不以静态概念图充当运行结果。
- 说明已实现、占位与待验证部分，尤其是正式模型、透明效果与真实设备性能。美术是否通过由用户反馈决定。
- 不复制没有实际价值的实现镜像测试；优先测试文件损坏、异步替换、资源边界等真实风险。

## 工作方式

采用轻量 BMAD 经验：记录方向、关键决定、短任务和验收条件；不安装完整方法工具链。每阶段交付可查看的成果，结合用户反馈迭代。用户未要求代理协作时不主动启动子代理。
